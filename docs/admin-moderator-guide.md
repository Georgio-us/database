# Руководство администратора и модератора базы

Статус документа: рабочее руководство по frontend-прототипу

Дата обновления: 26 сентября 2026 года

## 1. Для кого этот документ

Документ предназначен для администратора, руководителя агентства и будущего модератора базы

Он объясняет

- как устроены основные разделы
- куда заносить разные виды информации
- как поддерживать базу в порядке
- какие действия доступны в прототипе
- какие функции появятся после разработки backend
- какие правила ещё требуют согласования

Термины системы вынесены в отдельный [глоссарий](glossary.md)

## 2. Обозначения статуса

| Статус | Значение |
|---|---|
| Прототип | Экран и сценарий уже можно посмотреть, данные остаются демонстрационными |
| В разработке | Функция предусмотрена, постоянное хранение и серверная логика ещё не реализованы |
| Требует согласования | Нужны решение заказчика, реальные данные или правила площадки |
| Не входит в текущий этап | Функция не должна учитываться в текущем объёме |

## 3. Главный принцип работы

База общая для всего агентства

Все авторизованные риелторы должны видеть объекты и контакты собственников. Ответственный риелтор отвечает за объект и используется как внешний контакт, но коллеги могут помогать поддерживать сведения в актуальном состоянии

Любой риелтор сможет

- подтвердить актуальность
- изменить цену после разговора с собственником
- дополнить описание и характеристики
- добавить фотографию или телефон
- оставить комментарий
- поставить объект в резерв
- отметить объект проданным или снятым с продажи

Смена ответственного доступна руководителю или администратору. Значимые действия должны сохраняться в журнале

Статус реализации: `Прототип`. Реальное разграничение прав и аудит - `В разработке`

## 4. Роли

### Риелтор

- видит общую базу и контакты
- создаёт и редактирует объекты
- помогает актуализировать чужие объекты
- делает подборки
- работает с импортом и публикациями в пределах выданных прав

### Руководитель

- видит всю базу и состояние команды
- меняет ответственного риелтора
- контролирует просроченную актуализацию
- принимает решения по внутренним правилам

### Администратор

- управляет сотрудниками и справочниками
- меняет ответственных
- контролирует импорт и ошибки публикаций
- работает с архивом и системными настройками

Окончательная матрица прав: `Требует согласования`

## 5. Ежедневный порядок работы администратора

Рекомендуемая последовательность

1. Открыть Главную
2. Проверить блок `Требует внимания`
3. Посмотреть просроченную актуализацию
4. Проверить ошибки публикаций
5. Проверить последние импорты
6. Просмотреть уведомления об изменениях чужих объектов
7. При необходимости переназначить ответственного
8. Проверить новые значения справочников со статусом `На проверке`

Статус реализации: `Прототип`

## 6. Главная

Главная показывает рабочую сводку

- активные объекты
- объекты на актуализацию
- черновики
- ошибки публикаций
- последние изменения
- состояние команды
- состояние OLX и DIM.RIA

Счётчики сейчас демонстрационные. После backend они должны рассчитываться из реальных данных

Статус реализации: интерфейс - `Прототип`, реальные показатели - `В разработке`

## 7. Объекты

### 7.1. Что считается объектом

Объект - отдельное предложение о продаже недвижимости

Поддерживаемые типы

- квартира
- дом
- участок
- коммерческая недвижимость
- паркинг

В текущий объём входит только продажа. Аренда и посуточная аренда не входят

### 7.2. Куда заносить информацию

| Информация | Раздел карточки |
|---|---|
| Тип, адрес, район, цена и статус | Основное |
| Имя собственника, телефоны и мессенджеры | Контакт |
| Ответственный риелтор | Контакт |
| Площадь, комнаты, этаж и параметры объекта | Характеристики |
| Фотографии | Медиа и документы |
| Договор, техпаспорт и другие файлы | Медиа и документы |
| Условия показов и внутренняя информация | Внутренний комментарий |
| Причина изменения цены или статуса | Журнал действия и комментарий |

Внутренний комментарий не должен использоваться вместо структурированных полей. Цена должна находиться в поле цены, телефон - в контактах, район - в справочнике локаций

### 7.3. Минимальная карточка

Для первичного создания нужны

- тип недвижимости
- имя контакта
- телефон
- точный адрес
- административный район
- цена и валюта
- количество комнат для квартиры и дома

Черновик может быть неполным. Для активации квартиры дополнительно нужны общая площадь, этаж и этажность

### 7.4. Адрес и локация

- точный адрес хранится внутри базы
- номер квартиры хранится отдельно
- административный район обязателен
- микрорайон необязателен
- подзона необязательна

Не следует записывать `Приморский район`, `Аркадия` и `5-я станция Фонтана` в одно поле. Это разные уровни справочника

### 7.5. Контакт

Для прямого объекта указывается собственник или контактное лицо

Для партнёрского объекта указывается партнёр. Если доступен прямой телефон собственника, объект уже не считается полностью партнёрским

Можно хранить несколько телефонов. Старый телефон нельзя бесследно заменять после запуска журнала. Его нужно отметить неактуальным и добавить новый

### 7.6. Эксклюзив

Для текущего этапа достаточно

- признака `Эксклюзив`
- даты начала эксклюзива

Номер договора, дата окончания и комиссия пока не являются обязательной частью модели

### 7.7. Документы

Документы добавляются по необходимости, преимущественно для эксклюзивов и подготовки сделки

Документы не показываются клиенту и не отправляются на порталы

Срок хранения после продажи: `Требует согласования`. Предварительно документы сохраняются бессрочно

## 8. Статусы объекта

| Статус | Когда использовать |
|---|---|
| Черновик | Информации недостаточно для полноценной работы или публикации |
| Активный | Объект продаётся и доступен для работы |
| Требует актуализации | Срок подтверждения истёк или отсутствуют важные данные |
| Резерв | Объект временно зарезервирован, сделка ещё может не состояться |
| Продан | Сделка состоялась |
| Снят с продажи | Собственник передумал или предложение больше не действует |
| Архив | Объект больше не участвует в текущей работе |

Проданный и снятый объект должен переходить в архив с сохранением причины и истории

Истечение срока актуальности создаёт напоминание. Объект не скрывается и не снимается с публикаций автоматически

## 9. Актуализация

Актуализация означает подтверждение, что объект всё ещё продаётся и основные условия не изменились

Рекомендуемый процесс

1. Позвонить собственнику или партнёру
2. Проверить наличие, цену и возможность показа
3. Обновить изменившиеся сведения
4. Нажать подтверждение актуальности
5. Оставить комментарий, если есть важные договорённости

Период по умолчанию в прототипе - 14 дней. Доступные варианты - 7 и 14 дней

Окончательный период: `Требует согласования`

## 10. Подборки для клиентов

Подборка создаётся из выбранных объектов и получает отдельную публичную ссылку

Клиент может видеть

- фотографии
- публичное описание
- характеристики
- цену
- контакт ответственного риелтора

Клиент не должен видеть

- номер квартиры
- телефон собственника
- внутренние комментарии
- документы
- журнал изменений

Ссылку можно скопировать или подготовить для ручной отправки в Telegram

Автоматический Telegram-бот и Telegram Business: `Не входят в текущий этап`

## 11. Импорт Excel и CSV

Импорт предназначен для регулярной загрузки новых объектов, а не только для первоначального переноса базы

Предполагаемый процесс

1. Скачать шаблон или подготовить собственную таблицу
2. Загрузить XLSX, XLS или CSV
3. Выбрать лист
4. Сопоставить колонки файла с полями базы
5. Проверить предпросмотр
6. Разобрать ошибки и вероятные дубли
7. Подтвердить импорт
8. Скачать отчёт по пропущенным строкам

Не следует автоматически объединять вероятные дубли без понятного правила и подтверждения

Статус реализации: интерфейс - `Прототип`, чтение реальных строк и сохранение - `В разработке`

## 12. Публикации OLX и DIM.RIA

Для каждой площадки предполагается один корпоративный аккаунт агентства

В центре публикаций отображаются

- опубликованные объявления
- объявления, ожидающие обновления
- ошибки
- неопубликованные объекты
- дата последней синхронизации

Объекты можно отправлять и обновлять массово

Телефон ответственного риелтора желательно использовать во внешнем объявлении, если площадка и правила агентства это допускают

Статус реализации: интерфейс - `Прототип`, реальные API и фоновые очереди - `В разработке`

Доступы, лимиты и обязательные поля площадок: `Требуют согласования и проверки`

## 13. Команда

Раздел показывает

- сотрудников
- роли
- рабочие контакты
- количество объектов в работе
- просроченную актуализацию
- последнюю активность
- состояние пользователя

Нового сотрудника можно добавить как приглашённого. После backend приглашение должно отправляться на электронную почту

Отключение пользователя не должно удалять его историю действий

Статус реализации: интерфейс - `Прототип`, вход и реальные приглашения - `В разработке`

## 14. Настройки и справочники

### Агентство

Здесь хранятся название, город, рабочий телефон, электронная почта и адрес офиса

### Актуализация

Здесь задаётся период подтверждения и правила уведомлений

### Локации

Новая локация добавляется со статусом `На проверке`. Администратор должен проверить уровень и родительскую локацию перед использованием

Полный список Одессы: `Требует согласования с агентством`

### Валюты

Источник курса - Национальный банк Украины. Плановое обновление - один раз в день около 10:00

Статус реализации: интерфейс - `Прототип`, API НБУ - `В разработке`

### Публичные данные

Защищённые поля всегда скрыты. Фиксацию просмотров и водяной знак можно включать отдельно

### Подключения

OLX и DIM.RIA входят в ожидаемую поставку. Сайт подключается позже, когда появится сам сайт и будет согласован формат данных

## 15. Уведомления

Уведомления должны появляться при важных событиях

- коллега изменил объект
- объект требует актуализации
- публикация завершилась ошибкой
- импорт завершился с ошибками
- сменился ответственный
- объект отмечен проданным или снятым

Статус реализации: интерфейс - `Прототип`, хранение и доставка событий - `В разработке`

## 16. Архив и удаление

Архив используется для объектов, которые больше не участвуют в текущей работе

Архивирование должно быть обратимым. Окончательное удаление предполагается только для администратора

Точные сроки хранения документов и окончательные правила удаления: `Требуют согласования`

## 17. Что модератор не должен делать

- не удалять историю ради исправления ошибки
- не заменять старый телефон без сохранения предыдущего значения
- не смешивать административный район и микрорайон
- не загружать документы в публичные материалы
- не публиковать черновик с отсутствующими обязательными данными
- не объединять дубли без проверки
- не создавать новый справочник для единичного ориентира, который можно оставить в комментарии
- не считать старую базу Доминанта точным техническим заданием

## 18. Что пока не разработано

- авторизация и восстановление доступа
- PostgreSQL и постоянное хранение
- серверная валидация
- реальный аудит действий
- файловое хранилище фотографий и документов
- чтение и сохранение реальных Excel и CSV
- API НБУ
- API OLX
- API DIM.RIA
- фоновые очереди публикаций
- реальные публичные ссылки и аналитика просмотров
- автоматические уведомления
- резервное копирование и мониторинг

## 19. Что нужно получить от агентства

- реальный пример Excel или CSV
- перечень сотрудников и рабочих контактов
- окончательную матрицу прав
- правила удаления и хранения документов
- проверенный справочник локаций Одессы
- корпоративные кабинеты OLX и DIM.RIA
- реальные реквизиты агентства
- решение о выбранной комплектации проекта

До получения этих материалов интерфейс можно использовать для демонстрации и согласования, но не как рабочее хранилище данных
